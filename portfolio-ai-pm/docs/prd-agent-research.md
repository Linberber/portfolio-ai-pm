## 2. 产品概述

### 2.0 文档性质说明

> ⚠️ **本文档是一份基于推理构建的产品设计练习。**
>
> 本 PRD 是高校课程项目"Agent 方案设计"的深化版本。写作过程中未进行正式用户访谈或实地调研，文中所有用户画像、痛点描述、市场数据均来源于公开信息搜索 + 个人逻辑推理 + LLM 辅助分析。
>
> 这不是一份经过验证的产品方案，而是一份 **"如果我要做这个产品，我会怎么想"** 的思考记录。每一个判断都是假设——文档中已尽量标注清楚哪些是推理、哪些是待验证项。
>
> 如果我需要将这份 PRD 推进到真实落地，我会首先完成 §14.3 列出的验证计划。

---

### 2.1 产品背景

研究生入学后普遍面临选题焦虑——导师希望学生"自己找方向"，但学生常遇到以下问题（基于个人观察和公开讨论，非结构化调研）：

- 刚进入领域，知识储备不足，无法判断哪些方向值得做
- 手动检索文献效率低（有用户自述"看了一周论文还没形成判断"）
- 缺少系统方法来对比不同选题方向的可行性和创新性

现有工具（Google Scholar、知网、PubMed）只能检索，不能"帮你想"。AI 大模型的出现让"智能选题辅助"成为可能。

### 2.2 产品愿景

**让每位研究生 30 分钟内获得一份有据可查的选题分析报告。**

不是替用户做决定，而是帮用户看清每个方向的优势、风险和文献支撑，让用户带着结构化信息去和导师讨论。

### 2.3 核心价值主张

| 用户痛点 | 产品解法 |
|----------|----------|
| 不知道从何入手 | 输入模糊想法，Agent 拆解为具体选题方向 |
| 文献检索耗时 | 自动跨源检索，按可信度分级，输出结构化摘要 |
| 不会对比方向 | 从创新性、可行性、文献热度三维度打分，输出对比表 |
| 担心判断错误 | 设置 2 个人工确认节点 + 原文链接可查 |
| 跟导师沟通没底气 | 输出完整选题报告，可直接作为导学讨论材料 |

## 3. 市场背景与竞品分析

### 3.1 市场规模

- 中国在学研究生超 365 万人（2025 年教育部数据），其中理工农医类占比约 60%
- 选题是 100% 研究生必须经历的环节，每年新增目标用户约 120 万人
- AI 学术工具市场处于早期增长阶段，尚无占据主导地位的选题辅助产品

### 3.2 竞品格局

| 产品 | 类型 | 选题辅助能力 | 不足 |
|------|------|-------------|------|
| Google Scholar / 知网 | 搜索引擎 | 无 | 只有检索，无分析和对比 |
| Research Rabbit / Connected Papers | 文献关联图谱 | 弱 | 可视化文献关系，但不做选题评估 |
| Semantic Scholar | AI 文献搜索 | 弱 | 有引用分析，无选题建议能力 |
| Elicit | AI 文献问答 | 中 | 可提问，但无系统的选题对比流程 |
| ChatGPT / Claude / Kimi | 通用 AI 助手 | 中 | 可对话式选题咨询，但无结构化工作流、无来源分级、无结果验证 |
| **本产品差异** | **选题专用 Agent** | **强** | **结构化 8 步 Workflow + 多源分级 + 双人工确认 + 可验证输出** |

### 3.3 差异化定位

> 本产品不是"带 AI 的文献搜索"，而是"有文献严谨性的 AI 选题顾问"。

核心差异在于**人机协作的工作流设计**——不追求全自动，而是在关键节点设置人工确认，让用户保持控制权的同时大幅提效。

## 4. 目标用户

### 4.1 核心用户画像（假设，待验证）

> **声明**：以下画像基于公开社区帖（知乎、小木虫、Reddit r/PhD）中的研究生自述 + LLM 辅助归纳。**未进行一对一用户访谈。** 画像用于确定初始方向，正式开发前需用真实用户验证。

**生物专业研一学生·李同学（假设）**

| 维度 | 描述 | 来源 |
|------|------|------|
| **背景** | 本科生物科学，研究生进入神经科学方向，导师研究方向为神经调控 | 推理 |
| **痛点** | 导师给了"闭环神经调控"大方向，但自己不知道具体做什么 | 社区高频关键词 |
| **现状** | 在 PubMed 上搜到 300+ 篇论文，不知道哪些值得看，看了几篇也没形成判断 | 推理（类比社区自述） |
| **目标** | 找到一个 2 年内能做完、有创新点、数据可获取的具体选题 | 推理 |
| **使用场景** | 开题前 2-3 个月，每周花 1-2 天做文献调研 | 推理 |

**假设验证方式**：找 3-5 位生物/理工科研一学生做 15-20 分钟的轻量访谈，验证以上假设是否成立。核心验证问题：
1. "你从拿到导师方向到自己确定选题，中间经历了什么？"
2. "你做文献调研的具体步骤是什么？最痛苦的是哪一步？"
3. "如果有人给你一个选题分析报告，你希望里面有什么？"

### 4.2 用户痛点假设清单

以下痛点均为假设，每条附验证计划：

| 假设痛点 | 推理逻辑 | 验证方式 | 若为真优先级 |
|----------|----------|----------|-------------|
| "不知道怎么把模糊想法变具体选题" | 导学关系中常见"给你个方向自己想"，新手缺乏拆解方法论 | 访谈中问"上次你拿到导师方向后第一步做了什么" | P0 |
| "文献太多看不完，也不会筛选" | 检索结果量大但缺乏优先级排序能力 | 访谈中问"你一般怎么决定先看哪篇" | P0 |
| "不会对比不同方向" | 缺少多维度评估框架，容易只看"能不能做"忽略"值不值得做" | 访谈中问"你在两个方向之间纠结过吗，怎么选的" | P1 |
| "跟导师讨论时没底气" | 信息不对称——学生看到的信息远少于导师 | 访谈中问"你拿什么材料跟导师讨论选题" | P1 |

### 4.3 扩展用户群

| 用户群 | 场景 | 优先级 |
|--------|------|--------|
| 研一理工科研究生 | 首次选题 | P0（核心） |
| 研二换方向学生 | 原方向做不下去，需更换选题 | P1 |
| 本科生毕设 | 选题经验更少，对引导需求更强 | P1 |
| 青年导师/博士后 | 帮学生参谋选题，需快速了解新方向 | P2 |

## 6. 产品目标与成功指标

### 6.1 产品目标

> **关于数字的说明**：以下所有量化目标均为**设计初版目标值**，非行业基准也非经验值。目标是给团队一个明确的努力方向；上线首月获得的真实数据将成为后续目标的基线（baseline）。

| 目标 | 衡量方式 |
|------|----------|
| 降低选题调研门槛 | 用户从"不知道如何下手"到获得结构化选题报告的时间 ≤ 30 分钟 |
| 提升文献检索效率 | 对比用户手动检索耗时（需在 MVP 阶段实测基线值，目前为逻辑估算） |
| 成为用户与导师的对话工具 | 用户将报告用于导学讨论的比例 ≥ 60% |
| 建立用户信任 | 用户最终选题中，Agent 建议方向被纳入考虑的比例 ≥70% |

### 6.2 核心指标（MVP 阶段）

| 指标类型 | 指标名称 | 目标值 | 说明 | 测量方式 |
|----------|----------|--------|------|----------|
| 北极星指标 | 选题建议纳入率 | ≥70% | 设计初版目标，非行业基准 | 报告生成 1 个月后问卷回访 |
| 效率指标 | 用户操作时长 | ≤30 分钟/次 | 从进入流程到报告导出 | 后台埋点统计 |
| 质量指标 | 导师认可度 | ≥60% | 该值取决于导师个人偏好，仅作参考 | 用户反馈问卷 |
| 信任指标 | 原文点击/验证率 | ≥50% | 至少 1 次点击即计入 | 后台埋点 |
| 留存指标 | 二次使用率 | ≥40% | 一月内再次使用 | 后台统计 |

## 7. 功能需求详述

### 7.1 功能模块总览

```
┌──────────────────────────────────────────────────┐
│                   科研选题副驾系统                    │
├──────────┬──────────┬──────────┬──────────────────┤
│ 输入解析  │ 文献检索  │ 对比评估  │   交互反馈与报告   │
│ 模块     │ 模块     │ 模块     │   模块            │
├──────────┼──────────┼──────────┼──────────────────┤
│ · 自然语言 │ · 多源检索 │ · 三维度  │ · 结构化报告生成   │
│   输入    │ · 可信度  │   评分   │ · 人机确认节点     │
│ · 关键词  │   分级   │ · 对比表  │ · 反馈收集        │
│   提取   │ · 观点聚类 │ · 争论点  │                  │
│ · 选题方向 │          │   检测   │                  │
│   生成   │          │         │                  │
└──────────┴──────────┴──────────┴──────────────────┘
```

### 7.2 模块一：输入解析模块

**功能描述**：接收用户的自然语言输入，拆解为可检索的结构化信息。

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| F-01 | 用户输入研究领域、模糊想法、年份偏好、来源偏好 | P0 |
| F-02 | Agent 从输入中提取核心关键词（2-5 个） | P0 |
| F-03 | Agent 基于关键词生成 3 个候选选题方向，每个方向附 1-2 句说明 | P0 |
| F-04 | 用户可编辑/删除/新增候选方向 | P0 |

**输入字段**：
- 研究领域（必填）：如"神经调控"
- 初步想法（选填）：如"想开发柔性电子的闭环系统"
- 年份偏好（选填，默认近 5 年）
- 偏好的研究类型（选填）：理论/实验/计算/综述

**输出**：
- 2-5 个核心关键词
- 3 个候选选题方向（每条 ≤50 字）

**交互规则**：
- 若用户未填满必填项，给出示例引导而非报错
- 关键词提取结果对用户透明展示，用户可修改

### 7.3 模块二：文献检索模块

**功能描述**：对接多数据源，按选题方向检索文献，结构化梳理并分级。

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| F-05 | 对接 PubMed、arXiv、IEEE Xplore 等数据源进行检索 | P0 |
| F-06 | 每个方向检索 ≥5 篇相关文献（年份/来源可选） | P0 |
| F-07 | 按来源可信度对文献分级（L1/L2/L3，规则见 §10） | P0 |
| F-08 | 提取每篇文献的研究问题、方法、结论 | P0 |
| F-09 | 支持用户剔除不相关文献或追加关键词后重新检索 | P1 |
| F-10 | 观点聚类：识别相同方向的不同研究路线 | P1 |

**检索策略**：
1. 按候选方向的 2-3 个核心概念组合构建查询式
2. 优先检索 Level 1 来源（顶刊），再扩展至 L2/L3
3. 结果按"与候选方向的直接相关度"排序，非时间排序

### 7.4 模块三：选题评估与对比模块

**功能描述**：从多维度评估每个候选选题方向，输出可比的评分。

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| F-11 | 创新性评分（依据：近 3 年顶刊文献是否有重复） | P0 |
| F-12 | 可行性评分（依据：数据可获取性、实验条件要求、技术成熟度） | P0 |
| F-13 | 文献热度评分（依据：相关文献数量、发表趋势） | P0 |
| F-14 | 输出三个方向的对比评分表 | P0 |
| F-15 | 观点冲突检测：同一技术路线上的矛盾结论标注 | P1 |

**评分维度定义**：

| 维度 | 评分标准 | 权重 |
|------|----------|------|
| 创新性 | 1-10 分。近 3 年顶刊未覆盖 = 8-10 分；已有大量研究 = 1-3 分 | 35% |
| 可行性 | 1-10 分。所需条件用户可获取 = 8-10 分；需稀缺设备/数据 = 1-3 分 | 40% |
| 文献热度 | 1-10 分。上升趋势且有研究空白 = 8-10 分；过热但精细化 = 1-3 分 | 25% |

### 7.5 模块四：交互反馈与报告生成模块

**功能描述**：结构化输出选题报告，支持用户反馈收集。

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| F-16 | 生成结构化选题报告（含推荐方向、评分、依据、文献列表、风险提示） | P0 |
| F-17 | 所有文献提供原文链接（DOI/URL），可直接点击跳转 | P0 |
| F-18 | 每一项判断附依据说明（如"该方向近 3 年顶刊无重复研究"） | P0 |
| F-19 | 报告支持导出 PDF / 打印 / 分享链接 | P1 |
| F-20 | 报告生成后弹出简易反馈问卷 | P2 |
| F-21 | 生成 1 个月后通过邮件回访用户 | P2 |

## 8. 核心工作流

### 8.1 完整流程（8 步）

```
用户输入          ──→ Step 0：填写研究领域、模糊想法、偏好
                    ↓
Agent 拆解       ──→ Step 1：提取关键词，生成 3 个候选选题方向
                    ↓
👤 人工确认点 1   ──→ Step 2：用户增删改候选方向，确认后进入检索
                    ↓
Agent 检索       ──→ Step 3：多数据源检索文献，标记来源等级
                    ↓
👤 人工确认点 2   ──→ Step 4：用户查看文献列表，剔除无关文献 / 补充关键词
                    ↓
Agent 分析       ──→ Step 5：提取文献观点，聚类分析，生成结构化摘要
                    ↓
Agent 评估       ──→ Step 6：三维度评分 + 争议点标注 + 对比表
                    ↓
Agent 输出       ──→ Step 7：生成结构化选题报告，用户导出使用
```

### 8.2 异常流程

| 场景 | 处理策略 |
|------|----------|
| 检索结果为 0 | 提示用户放宽检索词或调整年份范围，不直接报错 |
| 用户输入极模糊（如"生物学"） | 引导用户缩小范围，给出更具体的子领域选项 |
| 全部候选方向文献仅有 L3 支撑 | 报告中明确标注"理论基础尚不成熟"风险提示 |
| 某方向文献过于单一（同一课题组） | 标注"研究者集中度偏高，独立验证有限" |

## 9. 系统边界

### 9.1 能做

- ✅ 解析自然语言需求，拆解为可检索的关键词
- ✅ 从多数据源检索并分析文献
- ✅ 生成选题方向并多维度对比
- ✅ 提供所有判断的依据（文献链接、数据来源）
- ✅ 输出结构化选题建议报告

### 9.2 不做

- ❌ 代替用户做出最终选题决策（人机协作原则）
- ❌ 完成实验验证（不在产品范围内）
- ❌ 后续论文撰写（独立的论文辅助工具可另外设计）
- ❌ 保证选题成功发表（无法控制的研究过程变量）
- ❌ 提供论文全文下载（版权限制，仅提供链接）

### 9.3 为什么这样画边界

本产品的设计哲学是**"给用户信息优势，但保持人的判断权"**。选题是研究生自己和导师共同决策的过程，产品定位为"信息整理 + 分析工具"，不是"决策替代者"。

## 10. 数据源与可信度规则

### 10.1 计划数据源

| 数据源 | 领域 | 说明 |
|--------|------|------|
| arXiv | 计算机/交叉学科 | 预印本，更新速度最快 |
| IEEE Xplore | 工程/电子/计算机 | 权威工程类数据库 |
| PubMed | 生物/医学/神经科学 | 生物医学权威数据库 |

### 10.2 来源分级规则

| 等级 | 定义 | 示例 | Agent 对待方式 |
|------|------|------|---------------|
| Level 1 (高可信) | 顶刊/顶会论文 | Nature/Science 子刊、IEEE Trans、CCF-A | 优先引用，高权重 |
| Level 2 (中可信) | 核心期刊/主流会议 | CCF-B/C 类、主流 SCI 期刊 | 正常引用 |
| Level 3 (参考) | 普通论文/预印本 | arXiv 预印本、普通会议 | 引用但加注"未经同行评审" |

**风险标注规则**：若某个选题方向的所有支撑文献均为 Level 3，报告中必须标注：

> ⚠️ "该方向目前仅依赖预印本或未正式发表的研究，理论基础尚不成熟，建议进一步验证。"

## 11. 人机协作设计

### 11.1 设计原则

本产品的核心设计原则是 **"人在回路中 (Human-in-the-Loop)"**——不是追求完全自动化，而是在提效的同时保留人的判断节点。

### 11.2 人工确认节点

| 节点 | 位置 | 操作 | 为什么需要人 |
|------|------|------|-------------|
| 确认点 1 | 关键词提取 → 文献检索之间 | 用户增删改候选选题方向 | Agent 不知道你的导师偏好、实验室条件、个人兴趣 |
| 确认点 2 | 文献检索 → 分析评估之间 | 用户查看文献列表，剔除无关文献或补充关键词 | Agent 可能检索到关键词匹配但实质不相关的文献 |

### 11.3 结果可验证性设计

每一项判断提供可验证依据：

| 判断类型 | 依据示例 |
|----------|----------|
| "创新性评分 8/10" | "近 3 年 Nature/Science/IEEE Trans 中未检索到相近研究（检索式：XXX，检索时间：2026-05-31）" |
| "可行性评分 6/10" | "该方向需柔性电子加工平台，若你所在实验室不具备该条件，可行性大幅降低" |
| "争议点标注" | "Smith et al. (2025) 报告准确率 92%，但 Chen et al. (2025) 指出该模型在跨数据集测试中泛化性不足 30%。[链接 A] [链接 B]" |

## 12. 非功能需求

| 类别 | 需求 | 说明 |
|------|------|------|
| **性能** | 单次完整流程 ≤30 分钟 | 含 2 次人工确认等待时间 |
| **性能** | Agent 处理响应 ≤30 秒/步 | 不含用户手动操作时间 |
| **可用性** | 首次使用时提供引导式交互 | 新用户有操作指引，避免空白页恐惧 |
| **可用性** | 错误信息使用用户语言 | 不说"LLM API timeout"，说"服务忙，请稍后重试" |
| **数据隐私** | 用户输入的研究想法不用于模型训练 | 在产品隐私政策中明确声明 |
| **兼容性** | Web 端优先，适配 Chrome/Safari/Edge | 暂不做移动端 |

## 13. MVP 与迭代计划

### 13.1 MVP（V1.0）

**范围**：生物/神经科学方向研究生，PubMed + arXiv 双源检索

**包含**：
- F-01 ~ F-08（输入解析 + 文献检索 + 基础对比）
- 两次人工确认
- 结构化报告生成（含文献链接）
- 基础反馈收集

**不包含**：
- IEEE Xplore 对接（V1.1）
- 观点冲突自动检测（V1.1）
- 邮件回访（V1.1）
- PDF 导出（V1.2）

### 13.2 迭代路线

| 版本 | 时间 | 核心交付 |
|------|------|----------|
| **V1.0 MVP** | 第 1-2 月 | 基础流程跑通（PubMed+arXiv），≥5 名用户试用并反馈 |
| **V1.1** | 第 3 月 | 新增 IEEE Xplore，观点冲突检测，用户体验优化（基于 MVP 反馈） |
| **V1.2** | 第 4 月 | PDF 导出，分享链接，扩展至化学/材料学科 |
| **V2.0** | 第 6 月 | 多语言支持，导师端视图，机构版 |

### 13.3 MVP 验证标准

MVP 达成以下标准即为验证通过：
1. ≥5 名真实研究生完成完整流程
2. ≥3 人将报告用于与导师讨论
3. 用户手动检索时间从 4 天降至 ≤1 天
4. 无用户报告"方向完全不相关"

## 14. 风险与假设

### 14.1 核心假设

| 假设 | 验证方法 |
|------|----------|
| 研究生愿意接受 AI 辅助选题 | MVP 阶段观察用户对 AI 建议的接受度 |
| 文献检索 API 可稳定调用 | 开发前完成 API 接入测试 |
| 用户能准确描述自己的研究兴趣 | 输入引导设计是否有效，通过用户测试验证 |
| 导师不排斥学生用 AI 辅助选题 | 问卷中增加"导师态度"选项 |

### 14.2 主要风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 文献检索质量不足（检索不准确） | 用户信任崩塌 | 人工确认点 2 作为拦截节点；持续优化检索策略 |
| LLM 幻觉（编造或篡改文献信息） | 严重——用户若发现一篇假文献，整个产品信任崩塌 | **三重防护**：① 文献只展示通过 API 检索到的数据，每条附原文链接；② Prompt 层约束——要求 Agent 引用文献时必须逐字复制 API 返回的标题/作者/年份，不得改写；③ 在报告中明确标注"以下信息来自 [数据源名称]，检索时间 [X]，请以原文为准" |
| 用户跳过人工确认节点 | 工作流形同虚设 | 设计上需要用户至少勾选确认才能进入下一步 |
| 版权/合规风险 | 法律风险 | 不提供全文下载，仅提供公开可查的文献元数据 |

### 14.3 验证计划——如果我要推进这个项目

> **这一节是我认为 PM 在写 PRD 后最该做的事，即使条件有限也应该写出来。**

我不是生物专业研究生，也没有用户调研资源。如果我要让这份 PRD 从"练习"变成"可推进的项目"，我会按以下顺序验证关键假设：

#### 阶段 0：低成本验证（0 成本，1-2 天）

| 验证什么 | 怎么做 | 通过标准 |
|----------|--------|----------|
| 痛点是否真实存在 | 在知乎、小木虫、Reddit r/PhD 搜索"选题""开题""选方向"等关键词，收集 ≥20 条用户自述，提炼共性痛点 | 5 条核心痛点中至少 3 条在社区中有 ≥3 条独立用户提及 |
| 竞品是否已覆盖 | 用 Elicit、Consensus、ChatGPT 分别走一遍"选题辅助"流程，记录它们的输出质量和缺失之处 | 确认竞品都不做"结构化选题对比"这件事（而非猜测） |
| LLM 是否能完成核心任务 | 用 Claude/GPT-4 做一次端到端测试：输入"神经调控方向选题"，让它执行 8 步 Workflow，观察每一步的输出质量 | 8 步中至少 6 步的输出在"可用"以上（人工判断） |

#### 阶段 1：用户验证（需要找到 3-5 名用户，1 周）

| 验证什么 | 怎么做 | 通过标准 |
|----------|--------|----------|
| 假设画像是否准确 | 找 3-5 位生物/理工科研一学生做 15-20 分钟访谈 | 画像中的痛点、场景至少 2/3 得到验证 |
| 用户对 AI 辅助选题的态度 | 访谈末尾问"如果可以有一个 AI 帮你做选题调研，你会用吗？最大的顾虑是什么？" | 至少 2 人表示愿意尝试；识别出主要的信任顾虑 |
| 8 步 Workflow 是否有遗漏 | 把 Workflow 画成纸面原型，让用户走一遍，观察哪里卡住 | 无关键步骤缺失；用户能在 5 分钟内理解整个流程 |

#### 阶段 2：方案验证（MVP 上线后）

| 验证什么 | 怎么做 | 通过标准 |
|----------|--------|----------|
| 产品是否真的帮到了用户 | 5 名种子用户完成完整流程，收集反馈 | ≥3 人表示"比我自己调研好" |
| 指标基线 | 记录首次使用的真实耗时、采纳率、导师态度 | 获得后续迭代的基线数据 |

| 术语 | 定义 |
|------|------|
| Agent | 基于大语言模型构建的智能体，能自主执行多步骤任务 |
